# 0.2.2 审计与修复

## 范围和证据等级

按用户指定的 Wide-Lens Engineering 工作流，选择 `debug / assured / full / independent`，实际使用 `main-only`，没有委派其他写入者。审计覆盖音乐组件、评论 API、Provider/Profile 与凭据边界、资源限制、旧版兼容、构建发布路径，并从升级及维护者隐私角度复查。

当前环境不提供 assured v5 所需的外部控制器、独立摘要通道、固定独立验证器及 OS 强制隔离，因此 assured 前置条件未满足。本报告只记录工程检查和实际工具结果，不是 assured v5 证明；没有生成或冒充控制器回执。

开始时插件仓库处于 `main`，基线提交为 `d3bbceb`，且已有自包含音乐组件和宿主评论接口的未提交工作。修改前已保留本地源文件副本及差异，不回滚既有功能。最新源码同时保留历史 sidecar 实现，但 sidecar、Node.js、原生程序及凭据不会进入当前插件包。

## 已修复

1. **回复的最新排序。** 上游楼中楼只提供最早优先的时间游标。按用户选择保留 `hot/new`，对完整可读取的回复线程做全局时间倒序，使用评论 ID 处理同时间的稳定顺序，再通过 keyset 游标分页。回复页仅声明实际支持的 `new`，不会把每个上游页独立倒转后冒充全局最新。
2. **超限路径。** 最多读取 500 条上游回复、十个 50 条请求；未完整读取不返回成功的局部“最新”结果，明确返回 `comments-limit-exceeded`。匹配宿主将其显示为线程排序上限，不提供无意义的立即重试。普通加载错误仍可以重试，已经加载的评论保留。
3. **游标作用域。** 版本化游标绑定歌曲、账号配置、排序、父评论及页大小。在发起上游网络请求前拒绝不匹配、过长、旧格式或异常偏移的游标。回复 keyset 还限制首屏时间范围，新回复插入或之前的回复删除不会造成按 offset 分页的跳项。
4. **宿主闲置缓存。** 最后一个查看者退出时裁剪闲置条目至 40 个；活跃查看者不受此上限挤出。此前源码已修复的旧版评论串源问题予以保留，并复跑了跨账号配置的降级测试。
5. **构建与 CI。** CI 改为实际使用的 `wasm32-unknown-unknown` 和新脚本参数，包含音乐插件格式、单测、Clippy、构建、包验证及产物上传。包构建只选取 `manifest.json` 和 `component/provider.wasm`，不再递归删除固定暂存目录或打入遗留文件。验证器读取指定产物目录，并核对当前清单身份、能力和权限。
6. **发布内容。** 文档更新为 0.2.2，并移除历史记录中的维护者昵称及个人目录。QA 配置、实际设置、账号数据、日志、依赖安装目录和构建输出保持忽略。

主要插件修改路径为 `plugins/music/src/netease_comments.rs`、`netease_catalog.rs`、`lib.rs`、清单/版本、构建验证脚本和 CI。宿主配套修改限于评论缓存、错误类型/本地化、限制提示及回归；宿主仓库没有在本次插件推送中发布。

## 边界与剩余限制

回复页处理为 O(n log n) 时间、O(n) 额外空间，n ≤ 500，每页会重新读取受限的完整线程；不在插件存储持久化评论正文。host 的网络、15 秒操作期限、fuel 和内存限制仍有效，平台错误或先到的资源限制仍会终止操作。顶层最多每页 50 条，去重使用有界 ID 集合。

评论测试只读，使用隔离配置，没有登录生产账号、发评或点赞。未找到超过 500 条回复的公开线程，此限制通过单元测试验证，未完成真实超大线程验收。本轮未重新验证 Spotify 真实授权、酷狗扫码或付费播放，也未控制用户桌面。不将公开评论读取当作登录、会员或音频播放验收。0.2.2 更新后应重新打开评论面板，使旧游标失效；要显示专门的超限提示，需要包含配套错误码与文案的宿主。
